## R1 LCP ≤ 1.8s — 見出しページで 1.9〜2.6s

- LCP 要素は Shippori Mincho の h1/h2。Lighthouse（simulated）は「観測時に Web フォントで描かれた文字」の描画を、シミュレーション上のフォント到着時刻（1.9〜2.6s）まで遅らせて見積もる。preload を全部外しても `/c` `/g` の値は変わらなかった（フォント到着で決まっている証拠）。
- 実際の挙動は `font-display: optional` なので、遅い回線ではフォールバック明朝で最初の描画時（FCP ≈ 1.1〜1.5s）に出る。実スロットリング（devtools）で測ると FCP = LCP ≈ 2.1〜2.4s（この PC の CPU 負荷込み）。
- ホームは LCP 要素が本文段落（システムフォント）なので 1.35s。

選択肢:
1. **見出しページの LCP 予算を 2.5s にする**（ホームは 1.8s のまま）。optional の実挙動を踏まえると、ユーザー体感は FCP で決まる。
2. 見出しも最初からシステム明朝にする（Shippori を捨てる）。LCP ≈ FCP になるが、A11 の判断（見出しの明朝が「らしさ」の中心）と矛盾。
3. LHCI を devtools スロットリングにする。optional の実挙動を測れるが、値が計測機の負荷で大きく揺れる。

## R2 TBT ≤ 200ms

- 揺れが大きく判定できない（同じビルドで 100〜500ms）。CI の値を見てから。
- カード単位の `<Suspense>` で hydration を分割すると `/c` の TBT は 200〜270ms まで下がるが、静的書き出しではその境界が「保留中」として書かれ、文書末尾でカードが差し替わる（`/g` で CLS 0.21）。何が SSR で suspend しているかを特定できるまで Suspense は外してある。

## R3 Content — 一行説明と個別ページの厚み
